# Security suite traceability (design §16.6)

One row per entry of the privileged-path register (`docs/DESIGN.md` §2.2, S1–S18). Every cited test was
opened and checked against the row's defense. Paths are relative to `test/`.

Status values: **proven** means existing tests assert the defense. **proven (new)** means a test in this
directory closes the gap. **partial** means part of the defense is untested, and the cell says what is missing.
**S2** means the cell needs the signed lanes, which are out of scope for S1.

Run this directory with:
`FOUNDRY_OUT=out/security FOUNDRY_CACHE_PATH=cache/security forge test --match-path 'test/security/*'`.

## Open items found while mapping

- **S15 / §16.6 wording.** §16.6 says migration to a "passthrough successor" is refused. The S15 mechanism
  (opcode scan, codehash pin, owner disclosure) refuses only a `DELEGATECALL` passthrough. A `CALL`-only
  passthrough controller is a plain runtime: it is accepted when the set pins its codehash and discloses its
  owner (`security/MigrationSuccessor.t.sol::test_call_only_passthrough_is_accepted_only_pinned_and_disclosed`). A
  ruling is needed on which reading is intended.
- **§16.6 items with no register row and no test yet:** the selector-surface test (`security/Surface.t.sol`,
  for I1 and I5) and "half-freeze unreachable".
